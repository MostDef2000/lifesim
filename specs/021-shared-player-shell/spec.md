# 021 — Shared player shell usability (#269 + bounded #59 residuals)

## Цель

Авторизованный игрок на любом экране видит доступную навигацию и честное
состояние игровых часов. Прямой вход (закладка/обновление) на не-world-маршрут
не должен оставлять игрока с недостижимыми вкладками на телефоне и вечным
«…» в часах. Попутно, в пределах уже принятой cream-оболочки: читаемость
поля свободного желания и текста inline-ошибки чата.

## Проблема

1. **Навигация (#269)**: `.topbar` переносится (`flex-wrap: wrap`), но строка
   `.tabs` — нет (`style.css`, базовые правила 26–30): min-content ширина
   полосы вкладок — вся однострочная лента (~9–10 кнопок), на ширине 390px
   правые вкладки уходят за вьюпорт и недостижимы.
2. **Часы (#269)**: `topbar()` (app.js) — чистый рендерер
   `S.world ? dayTime(...) : "…"`; `/world` загружают только `viewWorld` и
   `viewLocation`. Прямой вход на `#/chat`, `#/desire`, `#/profile` и т.д.
   оставляет `S.world = null` → часы навсегда «…» до визита на «Мир».
3. **Поле желания (#59 остаток в рамках #269)**: `#desire-input` — textarea
   (app.js, `renderDesire`) наследует глобальное правило управления
   (`input, select, textarea` → тёмный `#0c1014` фон) и читается как тёмная
   дыра на cream-оболочке `.desire-shell`.
4. **Inline-ошибка чата (#59 остаток в рамках #269)**: `.chat-error` использует
   `color: var(--warn)` (#e0b050) — на cream-панели чата контраст ≈1.7:1.

## Скоуп (точные пути)

- `backend/app/web/app.js` — routing-hook часов + context-owned bootstrap с
  общим joinable GET /world, валидацией тела, узким контекстным предикатом
  401 и stale-защитой публикаций мира в консумерах (viewWorld/viewLocation/
  pollEvents: null-drop + guard свежести; игровая логика экранов не меняется).
- `backend/app/web/style.css` — ТОЛЬКО: переносимость `.tabs`, scoped-правило
  `.desire-shell textarea`, цвет ТЕКСТА `.chat-error`.
- `specs/021-shared-player-shell/{spec,plan,tasks}.md` — этот трио.

## Требования

### A. Навигация

- N1. `.tabs` переносится нативным flex (`flex-wrap: wrap`); метки, порядок,
  active-состояние и privileged-гейт вкладки «Админ» не меняются.
- N2. Запрещено скрывать пункты (`overflow-x: hidden`), вводить меню-фреймворк
  или перекраивать desktop-раскладку там, где лента помещается.
- N3. Дополнительная высота шапки на мобильных допустима.

### Часы (bootstrap мира для topbar)

- C1. Хук в `route()` ПОСЛЕ auth/character-гейтов: только для реестровых
  маршрутов, которые сами не грузят `/world` (`#/world` и unknown-hash
  fallback диспетчатят `viewWorld`; `#/location/*` грузит сам). Аноним —
  login, без персонажа — креатор (существующие гейты не тронуты).
- C2. Single-flight В ПРЕДЕЛАХ текущей сессии-контекста: контекст =
  ссылка на `S.user` (новый объект после login/logout/удаления — relogin под
  тем же id = новая сессия) + id персонажа (обновления экрана заменяют объект
  `S.character`; id отличает реальную смену персонажа от refresh).
- C3. Fire-and-forget: не блокирует запрошенный экран, не создаёт
  необработанных rejection, не запускает feed/WS/poll, не меняет курсоры/
  action dispatch/погоду.
- C4. Успех: запись только если контекст актуален, полёт ещё текущий,
  ответ непуст и `S.world` пуст (новее — не перезаписывать); обновление
  `#clock` in-place (паттерн pollEvents).
- C5. Отказ: честное «н/д» вместо вечной загрузки; состояние переживает
  ре-рендеры topbar для того же контекста (topbar остаётся чистым рендерером);
  новый запрос (следующий route()/reload) имеет приоритет над меткой отказа;
  повторных циклов опроса нет.
- C6. Просроченные результаты (успех/отказ/401) отбрасываются по контексту И
  по владению слотом: полёт, потерявший слот более новому bootstrap'у, не
  публикует мир, не ставит метку отказа и не снимает чужой слот — даже если
  контекст (user-ссылка + charId) снова совпал (S21). Владение проверяется
  РАННИМ return'ом в обоих финализаторах (успех/отказ) ДО снятия слота,
  публикации и метки отказа — в т.ч. при потере владения в микротасковом
  зазоре между гейтом обёртки и обработчиком.
- C7. 401 обрабатывается в `api()` узким контекстным предикатом БЕЗ
  `noGlobal401`-обхода: STALE-ответ bootstrap-полёта (смена сессии/персонажа
  в полёте ИЛИ потеря слота более новому полёту) отбрасывается ДО глобальной
  мутации; CURRENT 401 (включая bootstrap) и все прочие вызовы сохраняют
  fail-closed путь (`S.user = null` + reroute, пин m132) с единственным
  добавлением fix03 — сбросом `S.world` (кэш мира не переживает сессию:
  401-деаут, logout, удаление аккаунта).
- C8. Тело 200-ответа `/world` валидируется ДО любой публикации (не-пустой
  не-массив объект с конечным неотрицательным числом `game_timestamp`);
  пустой/битый 200 — отказ с честным «н/д», никогда не кэш и не NaN-время
  (S19/S20).
- C9. Общий GET /world: bootstrap владеет единственным joinable-полётом на
  контекст; `viewWorld`/`viewLocation`/poll присоединяются к нему в тот же
  контекст (один GET при хэндоффе маршрута), без полёта — каждый грузит
  свежий (существующие refresh'ы не отключены; исторические счётчики
  S9=2/S10=1/S11=3 сохранены). Присоединённый ответ выставляется наружу
  только при актуальном владении+контексте (обёртка проверяет захваченный
  контекст ДО выдачи тела) — иначе `null`. Граница null/stale — В
  КОНСУМЕРЕ, сразу после присоединённого /world и ДО остальных запросов
  продолжения; гарантии консумеров РАЗНЫЕ: `viewWorld` захватывает
  контекст (user-ссылка + charId) и перепроверяет его перед общими
  записями; `viewLocation` сохраняет легаси-guard'ы (seq/hash/живые
  `!S.user || !S.character`); poll дропает только `null`/мёртвый
  `S.character` — полного session-guard'а и guard'а свежести погоды у
  poll НЕТ (легаси, вне скоупа). Общее: дроп молча — не сетевой сбой,
  pollFails не растёт; без общей записи, разыменования `.day` и покраски
  retry/toast/метки отказа (S22). Публикация мира дополнительно защищена
  guard'ом свежести: более ПОЗДНИЙ по завершению, но СТАРЫЙ по
  `game_timestamp` ответ того же контекста не перезаписывает уже
  опубликованный более новый мир/часы (viewWorld/viewLocation —
  мир+погода; poll — только S.world+часы, S23); экраны при этом рендерятся
  с актуальным общим состоянием.

### Контролы

- C1a. `.desire-shell textarea`: scoped cream-фон/текст/тёплый бордер/
  placeholder/focus на существующих provisional-токенах оболочки; размер и
  поведение не меняются; глобальное правило контролов не тронуто.
- C2. `.chat-error`: ТЕКСТ — тёмный тёплый error-ink `#93301f` (прецедент
  `.desire-drop`, ≈7.6:1 на панели чата), граница сохраняет `var(--warn)`
  (пин m63 + смысл предупреждения); жизненный цикл сообщения/статуса/ошибки
  не тронут; корневой `--warn` не меняется.
