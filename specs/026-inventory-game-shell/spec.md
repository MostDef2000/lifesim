# 026 — Shared game shell: inventory pilot (#367)

## Цель
Убрать разрыв между картой и инвентарём: тёплая общая навигация с теми же девятью разделами, видимым активным пунктом и контекстом персонажа. Сохранить утверждённый World (#297/#313), визуальный канон и механики. Одобрение: владелец подтвердил концепт #363–#366 и scope admission `commit approved`.

## Scope
- Переиспользовать PILL_TABS и единый рендерер dock на World и Inventory; не менять legacy topbar остальных маршрутов.
- Inventory loading/ready/empty/error использует одну оболочку и доступную навигацию; Admin сохраняет role gate.
- Имя, текущая локация, баланс (если известен), режим, часы, погода и состояние задачи — проекция существующих данных. При отсутствии данных честная подпись; никаких дополнительных игровых действий.
- Обновлять контекст из существующего poll и адаптера задач, сохранять clock bootstrap. Устаревший запрос инвентаря не должен заменять новый экран.
- Responsive shell резервирует место dock, без перекрытия содержимого.

## Не трогаем
Карта/POI, backend/API, экономика, управление, экипировка/продажа, глобальные CSS-токены, WS/feed, остальные системные экраны. Карточки, фильтры и интерактивность инвентаря — #368.

## Acceptance
1. World сохраняет девять destinations, aria-current и существующее поведение; Inventory использует тот же dock во всех состояниях.
2. Честные данные, роль Admin, возврат, прямой вход, ошибка и retry; no extra mutation/network requests from navigation rendering.
3. Устаревшая загрузка Inventory не перезаписывает другой маршрут.
4. Desktop 1440×900, mobile 390×844, keyboard/focus и отсутствие overflow подтверждаются в реальном браузере; скриншоты до/после.
5. Focused tests, node --check и bash scripts/check.sh; acceptance evidence до merge.
