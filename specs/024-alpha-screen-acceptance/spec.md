# 024 — Приёмка утверждённого набора экранов (#59, acceptance-only)

## Цель

Независимая приёмка текущего билда (байты main
`cbd174843196fa57a17125dba9d82bb1fd3a8384`, идентичные продовым) на
соответствие утверждённому визуальному референсу issue #59 по всей
канонической семье экранов. Вердикт по каждому критерию: pass / fail /
unverified (с причиной). Issue #59 закрывается только при полном
подтверждении; иначе — точный follow-up скоуп, issue остаётся открытым.

## Проблема (наблюдаемое)

#59 — утверждённый design-handoff (все design-критерии §5 отмечены),
использовался как implementation-зонтик: волны desire (#267/#268), shared
shell (#274), world first-view (#275), people (#276) доставлены и в проде.
Единого актуального доказательства соответствия всей канонической семьи
экранов утверждённому референсу нет — каждая волна доказывала только свой
фрагмент.

## Scope

- Только 3 файла этого трио. Продукт, CSS, тесты, API, механика, ассеты,
  зависимости — не меняются.
- Evidence (генерируется, НЕ коммитится): `shared/lifesim-059-closeout/`
  — `report.json` + `shots/`.
- GitHub: итоговая запись в #59; закрытие — только при полном pass.

## Exclusions

- Appearance/Settings repaint — вне канонического утверждённого набора
  (VISUAL-BIBLE §43/§48), отдельная консистентность, не условие закрытия.
- #55 (финальная палитра/типографика/иконки), #195 (геймплей диалогов) —
  отдельные issues, не зависимости этой приёмки.
- Backend/API/механика/схемы; pixel-perfect spacing; новые трекнутые
  тесты и фреймворки.

## Requirements

- R1 — матрица критериев: экраны S1 island-main, S2 district-zoom,
  S3 settlement-local, S4 scene-flux, S5 dialogue, S6 inventory, S7 tasks,
  S8 desire, S9 time-weather; UX-правила U1 (Living Map — главный
  визуальный слой world screen), U2 (UI не перекрывает мир без причины),
  U3 (scene view: крупный visual + contextual actions), U4 (dialogue
  всегда содержит свободное текстовое поле), U5 (preset replies —
  shortcut, не единственный ввод), U6 (desire — отдельный first-class
  экран), U7 (роли персонажа читаемы в profile/social context), U8
  (weather/time визуально влияют на карту); тон T1 (мягкий/тёплый/
  привлекательный/grounded, без детскости и glossy mobile-game).
- R2 — оба вьюпорта: 390×844 и 1440×900.
- R3 — воспроизводимый пруф на критерий: скриншот + машинная проверка.
- R4 — честный unverified с причиной; выдуманных pass нет.
- R5 — вердикт close/follow-up зафиксирован в #59.
- R6 — байт-идентичность приёмки продовым байтам (sha256 style.css
  `7305fdb4…`, app.js `33d7bb96…` локаль == прод).

## NFR

стенд одноразовый (сид `--days 0 --population 20 --seed 42`, БД в /tmp,
порт 8831). Единственная мутация на стенде — admin timescale для S9 из
отдельного контекста. Структурная правда — существующие зелёные сьюты
(`bash scripts/check.sh`), этот wave не добавляет трекнутых тестов.
