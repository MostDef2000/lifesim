# ВЛ1: Рейнеке — Конституция проекта

Конституция задаёт неизменные архитектурные принципы. Ослабление любого из них запрещено; изменение — только отдельным решением с фиксацией в этом документе.

## Принцип 1. Сервер — источник истины

LLM предлагает intent → Simulation Engine валидирует → БД фиксирует.
Никакое значимое событие не существует только в тексте: травма NPC = запись в `character_health`, деньги = `balance`, покупка = объект собственности. LLM не имеет права напрямую мутировать состояние мира.

## Принцип 2. Мир обязан жить без LLM

Если система не работает без LLM — она спроектирована неверно.
- **Tier 0 (по умолчанию)** — детерминированная симуляция / Utility AI.
- **Tier 1/2 (LLM)** — только для: конфликтов целей, диалогов, интерпретации поручений игрока, необычных событий.
- LLM — не симулятор мира и не обходит Action Validator.

## Принцип 3. Event log + ledger

- Все значимые изменения мира — события в `world_events`.
- Все денежные изменения — транзакции ledger; прямые мутации балансов запрещены.

## Принцип 4. 18+ и согласие

Проект строго 18+. Жёсткие правила мира — часть validation layer, а не текстовые обещания:
- Романтический/сексуальный контент — только между однозначно совершеннолетними персонажами; возраст — серверное поле, не вывод LLM.
- Никакого сексуального насилия.
- Никаких реальных людей как прототипов персонажей.
- Взаимодействия между реальными игроками — только через явный consent-механизм (`interaction_permissions`), никогда не выводимый из свободного текста.

## Принцип 5. Действие → состояние мира → реакция окружающих → последствия

Причинно-следственная связность — критерий каждой фичи: действие должно изменить состояние мира, вызвать реакцию окружающих и оставить последствия.

## Требуемые артефакты

Значимые изменения оформляются через `specs/<feature>/{spec,plan,tasks}.md`. Источник истины по архитектуре — `docs/SPEC-V0.1.md`.

## Губернанс

Проект-специфические контракты могут уточнять принципы, но не вправе ослаблять серверную истину, event log/ledger, возрастные и consent-правила, верификацию и acceptance evidence.
